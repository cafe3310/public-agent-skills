# 📖 Hugging Face 数据统计 (hugging-face-stat) 使用指南

这个技能专门为您解决一个痛点：**Hugging Face 网页端通常只显示“最近 30 天”的下载量，而隐藏了“历史总下载量”。**

通过这个技能，您可以让 Agent 直接查出任何公开模型、数据集或 Space 的真实历史热度和详细运行规格。

---

## 🌟 核心能力

- **挖掘历史总量**：获取模型或数据集自发布以来的累计总下载次数。
- **透视 Space 硬件**：查看某个 Space 运行在什么显卡上（如 T4, A10G, A100）以及使用的开发框架。
- **组织资产汇总**：一键导出某个组织（如 `google`, `meta-llama`）下所有热门模型的下载排行。
- **数据美化**：自动对大数据进行千分位处理，易于阅读。

---

## 🚀 如何让 Agent 为您工作？

您只需用自然语言向您的 Agent 提问即可。以下是一些推荐的对话例子：

### 1. 查询模型或数据集的真实热度
> **“帮我查一下 `google-bert/bert-base-uncased` 这个模型一共被下载了多少次？”**
> *（Agent 会告诉你最近 30 天下载量，以及最重要的：历史总下载量）*

### 2. 深入了解某个 Space 的运行成本
> **“这个 Space `multimodalart/flux-tarot` 跑在什么硬件上？它的点赞多吗？”**
> *（Agent 会反馈该 Space 的运行状态、显卡规格和点赞数）*

### 3. 统计某个组织的影响力
> **“看看 `inclusionAI` 这个组织下最火的前 10 个模型分别是什么？”**
> *（Agent 会列出该组织的所有模型总数，并按热门程度为您排序）*

### 4. 数据集查询
> **“查询数据集 `clin-re/medical_reports` 的下载统计和创建时间。”**

---

## 🛠 技术细节（供了解）

- **数据来源**：直接调用 Hugging Face 官方 API 的扩展参数。
- **脚本支持**：内置 `hf_stats.sh` 脚本，处理了复杂的 JSON 解析和错误重试逻辑。
- **局限性**：官方 API 不提供 Space 的访问量（Views），因此我们使用点赞数和硬件投入作为衡量热度的替代指标。
