# 阶段三：Idea 吸收与切面边界确定规范 (Phase 3: Inbox Harvesting & Aspect Bounds)

## 1. 阶段目标与收敛流转机制

阶段三的目的是**吸收乱序的想法与参考产品观察，并将其精密归流收敛至确切的切面边界中**。

在此阶段，Agent 必须支持接收用户随意描述的大量非结构化想法，并通过以下机制进行收敛：

1. **Inbox 原始收集区 (D00-inbox)**：
   * 将用户描述的原始文本存入 `D00-inbox/` 目录；
   * 每条记录包含：【原文】（用户原始表述）与【简洁分析】（解题方向与拟映射切面）。
2. **参考功能点记录与 AOP 映射 (功能点拆解、图片归档与切面对齐)**：
   * **功能点记录**：记录参考产品或对标系统的模块及 UI 交互功能点。
   * **图片与附件归档**：
     - 若包含界面截图或媒体素材，保存至笔记库附件目录；
     - 使用 Markdown 或笔记库语法在功能点文档中嵌入。
   * **功能点文档结构 (`D52-xx`)**：
     - 在 `参考产品/<product-id>/D52-功能点列表/` 目录下创建独立功能点文档。
   * **AOP 切面对齐映射**：
     - 建立与目标产品 AOP 切面的映射表，标注参考功能细项、对应 AOP 切面 (如 [[D3x-xx]]) 及工程参考价值。
   * **更新概览索引**：
     - 在参考产品 AOP 概览文档（如 `D51-xx.md`）中追加对应功能点链接。


3. **明确边界界定 (In/Out Bounds)**：
   * 每一个切面必须显式书写 **✅ 包含什么 (Includes / 范围内)** 与 **❌ 不包含什么 (Excludes / 范围外)**；
   * 必须采用**合理抽象的叙述**（如“高展示性动态素材”、“前台结构化分析产出”、“主流接口规范”），绝不硬编码过分具象的临时例子，避免干扰后续需求生成。
4. **反向质询与交互审核 (/roast-me Interaction)**：
   * Agent 主动针对切面的混淆点发起 `/roast-me` 式的反向质询与审视（如提示词控制范围、解耦运营与二方交付、零强制输入反馈），由用户确认最终结论。

## 2. 典型切面抽象定义范例

* **参数调试与控制切面**：
  * ✅ 包含：核心引擎参数显式调节、系统指令作用域、官方预设工具一键勾选、代码导出入口；
  * ❌ 排除：使用者自定义手写扩展代码、系统缓存显式调试开关、长程复杂流程。
* **高频高价值标杆场景切面 (求“精”)**：
  * ✅ 包含：采用有向图/图结构 (Graph Workflow) 架构、值得团队精细调优与专属评测、高性能消耗与复杂逻辑流转的硬核标杆场景；
  * ❌ 排除：零碎轻量且未经深度打磨的简单交互用例。
* **通用容器与配置化演示场景切面 (求“多”)**：
  * ✅ 包含：展示系统在特定场景下的适用能力，基于场景 `x` 对应的初始化 Git 仓库拉取三要素（初始文件系统 VFS、执行配置、示例指南）拉起轻量沙箱，支持前台现场实操与源码复刻；
  * ❌ 排除：需要专属深度框架调优与复杂图结构的长程场景。
* **会话导出与反馈跟踪切面**：
  * ✅ 包含：零强制输入的极简反馈流程，一键生成唯一反馈 Case ID，支持全渠道触达沟通；
  * ❌ 排除：面向工程师的复杂调试日志分析（由后台系统承载）。
