# Subcommand: `/guide test` (测试用例管理与测试执行)

## 1. 核心定位与双重模式

`/guide test` 是系统的质量保障指令，具备**记录维护测试用例集**与**触发全面测试验证**双重能力：

- **模式 A：记录 / 维护测试用例集** —— 用户提出测试设计诉求时，在 `tests/` 目录下创建或版本化更新测试用例清单；
- **模式 B：触发 / 执行测试验证** —— 用户下达测试指令时，Agent 尽最大努力执行测试（包括运行自动化命令与引导用户手动核对人工用例）。

---

## 2. 模式 A：测试用例集管理与结构规范

测试用例以 Markdown 格式保存在项目根目录下的 `tests/` 目录中，使用**时间戳目录**进行严格的版本化管理：

```text
tests/
└── YYYY-MM-DD-HH-mm-testsuite/
    ├── readme.md                         # 概述、前置环境要求、执行方法
    ├── part1-{模块名}/
    │   ├── case1-{简述}.md
    │   └── case2-{简述}.md
    └── part2-{模块名}/
        └── case1-{简述}.md
```

### 用例文档标准结构 (`case{序号}-{简述}.md`)
- **ID & 标题**：唯一标识与简明用例名
- **前置条件**：执行测试所需的初始状态或配置
- **输入 / 操作步骤**：具体的交互或执行数据
- **预期结果**：明确、可判定的成功断言指标
- **实际观察记录**：（可选，执行后填入）

### 测试用例集版本更新机制 (-EDITING 模式)
1. 首次创建：直接在 `tests/` 下建立新的时间戳目录并编写用例；
2. 版本演进：将当前最新的测试集完整复制一份，命名为 `tests/YYYY-MM-DD-HH-mm-testsuite-EDITING/`；
3. 在新目录下进行增删改，直到用户确认无误；
4. 经用户确认后，去掉 `-EDITING` 后缀完成发布；
5. 在 `TODO.md` 和后续的开发日志中引用新版本。

---

## 3. 模式 B：触发并执行全面测试 (Execute Tests)

当用户输入 `/guide test` 或要求执行测试时，Agent 按以下层级尽力全面排查：

### 1. 自动化检查 (Automated Checks)
- 主动运行项目具备的编译、语法、类型守卫与自动化测试套件（如 `npm run build`、`npm test`、`pytest` 等）；
- 捕获并修复出现的任何编译错误或断言失败。

### 2. 人工检查清单引导 (Manual Checklist Guidance)
- 对于涉及 UI 视觉、复杂交互、硬件/环境依赖等无法完全自动化的测试用例：
- Agent 必须**清晰列出精确的操作步骤与断言清单，引导用户进行手动验证**；
- 示例：
  ```markdown
  ### 📋 需人工复核的测试用例清单：
  - [ ] **TC-01 [配置收起面板]**：点击右上角「◨ 收起」按钮，确认左侧面板是否平滑占满 100% 宽度；
  - [ ] **TC-02 [时间语义]**：查看「12306接入」群，确认其时间是否为空，而非显示过去的 UTC 扫描时间。
  ```

### 3. 测试结论汇报
向用户输出完整的测试执行总览：
- **自动化测试**：通过 / 失败（附带输出日志）；
- **人工用例**：已引导项与等待用户反馈项；
- **质量门禁**：若有关键失败项，明确阻断任务完成状态，提出排查建议。
