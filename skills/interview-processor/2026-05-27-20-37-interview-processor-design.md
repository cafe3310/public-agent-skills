# 面试记录处理技能 (interview-processor) 设计与建模文档

## 背景与问题说明

- **背景**：用户在招聘过程中，有在面试前规划大纲、面试后整理真实提问、以及面试后撰写面试纪要与自我评估的需求。为了能将这些高价值的招聘过程数据沉淀下来，需要设计一个 Agent 技能。
- **提出的问题**：
  1. 如何将这三个独立的阶段（面试大纲规划、提问纠错整理、纪要与自评总结）串联为一个完整的工作流。
  2. 如何将生成的数据以结构化的形式存储进基于 `memories-off` 的本地知识图谱中。
  3. 如何让技能适应用户（面试官）当前岗位与团队背景的变化。
- **为什么需要这份文档**：本设计文档详细定义了本技能的知识建模结构、动态上下文机制和具体工作流设计，为技能的最终开发提供坚实的逻辑框架。

## 1. 知识图谱实体建模设计 (KG Entity Modeling)

为了在基于 `memories-off` 的知识图谱中沉淀面试信息，我们设计了三类实体结构，并使用 WikiLinks 和关系谓词进行双向关联。

### 1.1 面试方法论 (Interview Methodology)
*   **命名规范**：`[领域/岗位]专家面试风格-YYYYMMDD` （例如：`iOS专家面试风格-20250718`）
*   **实体类型**：`面试方法论`
*   **核心章节**：
    *   `## 面试风格与偏好`：列出面试官的原则、关注点、风格特征。
*   **关联关系**：
    *   （无显式出站关系，作为元知识被其他实体引用）

### 1.2 面试问题集 (Interview Question Set)
*   **命名规范**：`[领域/岗位]面试问题集-YYYYMMDD` （例如：`大模型产品面试问题集-20250729`）
*   **实体类型**：`面试问题集`
*   **核心章节**：
    *   根据技术方向划分的 H2 章节（例如 `## 核心认知与边界理解`、`## 系统设计与成本控制` 等）。每个章节下使用无序列表列出具体问题。
*   **关联关系**：
    *   通过出站关系 `target_methodology` 指向其对应的 `[领域/岗位]专家面试风格-YYYYMMDD` 实体。

### 1.3 面试记录 (Interview Record)
*   **命名规范**：`对[候选人姓名]的面试总结 (YYYY-MM-DD)`
*   **实体类型**：`面试记录`
*   **核心章节**：
    *   `## 基本信息`：包含候选人姓名、招聘类型（校招/社招/数字马力）、岗位名称。
    *   `## 面试反馈`：包含建议层级、优势、不足、结论。
    *   `## 沟通记录与评价`：详细记录两人讨论的话题及面试官评价（包含团队介绍、自由提问阶段）。
    *   `## 面试官表现自评`：由 AI 作为专家对面试官提问风格、得体度、是否充分展示、重要考察遗漏等的客观评估与要求。
*   **关联关系**：
    *   `use_style`：指向 `[领域/岗位]专家面试风格-YYYYMMDD`。
    *   `use_question_set`：指向 `[领域/岗位]面试问题集-YYYYMMDD`。
    *   `candidate`：指向候选人实体（如知识图谱中存在候选人）。

## 2. 动态上下文配置 (Dynamic Context)

为了解决“面试官当前的岗位和之前有所不同”这一问题，我们将面试官的背景知识抽象为一个特殊的图谱实体或配置文件。

*   **方案 A (推荐 - 知识图谱优先)**：在知识图谱中维护一个实体 `我自己的面试官画像`（或特定岗位专家画画像），其 `entityType` 为 `个人画像`。
    *   该实体中包含 `## 当前岗位与团队` 和 `## 个人面试偏好`。
    *   在执行技能前，Agent 通过 `memocli search-entities` 检索此画像实体，动态加载当前团队介绍背景和个人风格。
*   **方案 B (环境配置优先)**：在技能目录下提供一个 `config.json` 或在运行命令时传入环境变量 `INTERVIEWER_ROLE`。

我们选择 **方案 A**，因为这极其符合 `memories-off` 知识图谱“持续学习”和“自包含”的定位。面试官的岗位改变时，只需通过 `memocli` 更新自己画像实体的 H2 章节内容即可。

## 3. 三大核心工作流设计 (Workflows)

### 3.1 任务一：规划面试题目 (Pre-Interview)
1.  **输入**：岗位信息 JD、候选人简历、特殊面试要求、(可选) 面试官个人画像/面试风格。
2.  **处理**：
    *   Agent 读取岗位和简历，提炼出候选人的关键背景和需要验证的疑点（例如“为什么火速跑路”、“简历真实性”）。
    *   结合面试官画像中的风格偏好（如务实、关注“为什么”而非“怎么做”），定制化生成一份面向特定层级的面试大纲。
3.  **输出**：结构化面试大纲（包含重点关注方向和预设追问）。

### 3.2 任务三：整理真实提问 (Post-Interview: Question Extraction)
1.  **输入**：面试转写文本。
2.  **处理**：
    *   分析转写内容，识别同音词、错字。
    *   过滤非提问性对话，完整列出面试官的所有提问和追问。
    *   去除过度口语化的表达，规范为书面语言，并按技术/业务方向分类。
3.  **输出**：
    *   标准化的面试问题集（格式见原始需求例子）。
    *   (可选) 引导 Agent 建议用户，将这些问题沉淀到关联岗位的 `面试问题集` 实体中。

### 3.3 任务二：整理面试总结与评估 (Post-Interview: Summary & Feedback)
1.  **输入**：简历、JD、转写文本、面试官笔记/评价草稿。
2.  **处理**：
    *   **提取沟通记录**：整理讨论话题，对照面试官笔记中认为对方回答得如何。
    *   **总结候选人特质**：客观、中立地评估项目熟悉度、基础专业度、聪明度、诚实度等，无法确定的用 `BLANK` 留空。
    *   **自省评估**：以专家级视角对面试官的表现提出建议和要求，纠正偏见，指出遗漏维度。
3.  **输出与图谱写入**：
    *   生成完整的 `对[候选人姓名]的面试总结 (YYYY-MM-DD)` Markdown 实体。
    *   调用 `memocli create-entity` 将其存入知识库，并建立与 `面试方法论` 和 `面试问题集` 的出站关系。
