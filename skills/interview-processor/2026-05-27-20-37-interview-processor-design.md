# 面试记录处理技能 (interview-processor) 设计与建模文档

## 背景与问题说明

- **背景**：用户在招聘过程中，有在面试前规划大纲、面试后整理真实提问、以及面试后撰写面试纪要与自我评估的需求。为了能将这些高价值的招聘过程数据沉淀下来，需要设计一个 Agent 技能。
- **提出的问题**：
  1. 如何将这三个独立的阶段（面试大纲规划、提问纠错整理、纪要与自评总结）串联为一个完整的工作流。
  2. 如何将生成的数据以结构化的形式存储进基于 `memories-off` 的本地知识图谱中。
  3. 如何让技能适应用户（面试官）当前岗位与团队背景的变化。
  4. 如何在技能中合理组织文档结构，以便于 Agent 读取和执行。
- **为什么需要这份文档**：本设计文档详细定义了本技能的物理文件结构、知识建模结构、动态上下文机制和具体工作流设计，为技能的最终开发提供坚实的逻辑框架。

## 2. 知识图谱实体建模设计 (KG Entity Modeling)

为了在基于 `memories-off` 的知识图谱中沉淀面试信息，我们设计了四类实体结构，并使用 WikiLinks 和关系谓词进行双向关联。

### 2.1 个人画像 (Interviewer Persona)
*   **命名规范**：`我自己的面试官画像`
*   **实体类型**：`个人画像`
*   **核心章节**：
    *   `## 当前岗位与团队`：描述当前的岗位名称、所负责团队及其业务。
    *   `## 个人面试偏好`：面试官自述的提问原则和面试理念。
*   **关联关系**：
    *   作为全局环境配置，被后续的面试流程读取。

### 2.2 面试方法论 (Interview Methodology)
*   **命名规范**：`[领域/岗位]专家面试风格-YYYYMMDD` （例如：`iOS专家面试风格-20250718`）
*   **实体类型**：`面试方法论`
*   **核心章节**：
    *   `## 面试风格与偏好`：列出面试官在该领域的提问原则、关注点、风格特征。

### 2.3 面试问题集 (Interview Question Set)
*   **命名规范**：`[领域/岗位]面试问题集-YYYYMMDD` （例如：`大模型产品面试问题集-20250729`）
*   **实体类型**：`面试问题集`
*   **核心章节**：
    *   根据技术方向划分的 H2 章节（例如 `## 核心认知与边界理解`、`## 系统设计与成本控制` 等）。每个章节下使用无序列表列出具体问题。
*   **关联关系**：
    *   出站关系 `target_methodology` 指向其对应的 `[领域/岗位]专家面试风格-YYYYMMDD` 实体。

### 2.4 面试记录 (Interview Record)
*   **命名规范**：`对[候选人姓名]的面试总结 (YYYY-MM-DD)`
*   **实体类型**：`面试记录`
*   **核心章节**：
    *   `## 基本信息`：包含候选人姓名、招聘类型（校招/社招/数字马力）、岗位名称。
    *   `## 面试反馈`：包含建议层级、优势、不足、结论。
    *   `## 沟通记录与评价`：详细记录两人讨论的话题及面试官评价（包含团队介绍、自由提问阶段）。
    *   `## 面试官表现自评`：由 AI 作为专家对面试官提问风格、得体度、是否充分展示、重要考察遗漏等的客观评估与要求。
*   **关联关系**：
    *   `use_style`：指向 `[领域/岗位]专家面试风格-YYYYMMDD`。
    *   `use_question_set`：指向 `[领域/岗位]面试问题集-YYYYMMDD`。
    *   `candidate`：指向候选人实体（如知识图谱中存在候选人）。

## 3. 动态上下文配置 (Dynamic Context)

为了解决“面试官当前的岗位和之前有所不同”这一问题，我们将面试官的背景知识抽象为知识图谱中的 `我自己的面试官画像`。
- 在执行任何子任务前，Agent 会被要求首先通过 `memocli search-entities "我自己的面试官画像"` 或 `memocli search-entities "我自己的面试官画像" --names-only` 查明是否存在，并读取该实体获取 `## 当前岗位与团队` 中最新的背景介绍。
- 如果不存在该实体，Agent 将引导面试官初始化该实体，以确保数据的一致性。

## 4. 三大核心子任务工作流设计 (Subtasks)

### 4.1 task-1-pre-interview.md (规划面试大纲)
1.  **输入**：岗位信息 JD、候选人简历、特殊面试要求、(可选) 面试官个人画像/面试风格。
2.  **处理**：分析 JD 与简历，提取关键的验证疑点。结合面试官画像偏好，生成定制化面试大纲。

### 4.2 task-3-post-interview-questions.md (整理真实提问)
1.  **输入**：面试转写文本。
2.  **处理**：识别同音词与错字，过滤非提问对话，去口语化规范，按方向分类。
3.  **输出**：标准化的面试问题集。引导建议用户更新/创建至 `面试问题集` 实体。

### 4.3 task-2-post-interview-summary.md (整理面试总结与评估)
1.  **输入**：简历、JD、转写文本、面试官草稿笔记。
2.  **处理**：整理话题及评价，评估候选人特质（项目熟悉、专业度等），对面试官提问和风格提供专家级评估。
3.  **输出**：格式化为 `对[候选人姓名]的面试总结 (YYYY-MM-DD)` Markdown 并调用 `memocli` 写入知识库。
