# 子流程 03: 结构化大纲梳理 (Understanding Prompt)

## 1. 目标
大纲梳理阶段。根据收集的创作参数和速记想法，结合 `rules/platforms.md` 规范，引导用户选择优化侧重，输出包含内联标注的结构化初版大纲。

---

## 2. 执行规程

### 2.1 选择优化侧重
在大纲生成前，提问让用户确认以下两个维度偏好：
- **Hook 侧重**：如何设计开头吸引读者（如反常识对比、痛点揭示、故事引入）。
- **调性选择 (Tone)**：文章的叙事调性（如犀利批判、中立科普、干货分享）。

> **交互与等待限制**：
> 1. 环境支持 `ask_question` 时，必须调用该工具呈送 Hook 和 Tone 的选项。
> 2. 提问后必须停止，等待用户做出选择。**严禁**提前生成大纲、推进下一步或做出「我接下来将为您做 X」等预告。

### 2.2 读取规则与整合
读取本技能根目录下的 `rules/platforms.md`（注意：该文件位于本技能的 `rules/` 文件夹中，而非用户当前的写作项目目录）中对应发布渠道的排版、调性与 Hook 规范，结合 `01-用户原始输入.md` 与 `02-用户想法记录.md` 整理大纲。

#### 信息支撑策略
- **本地优先**：优先使用 `rules/` 和 `samples/` 目录下的参考文件。
- **在线检索**：若观点缺乏事实支撑或最新数据，使用 `sub-skills/agent-browser` 检索，并在大纲中注明来源 URL 或标注「需核实」。

### 2.3 编写初版大纲
大纲内容包含：
- **🎯 核心论点提炼**
- **📂 结构化逻辑大纲**（分段脉络、核心素材点）

### 2.4 内联标注规范
对于大纲中缺少依据、存疑或需要进一步展开的段落，必须以引用块 `>` 形式就地标注：

| 类别 | 前缀格式 | 适用场景 |
| :--- | :--- | :--- |
| 待调查 | `> 🔍 待调查：` | 缺少事实、数据支撑，需联网检索核实 |
| 待分析 | `> 📊 待分析：` | 有数据但需进一步解读或横向对比 |
| 风险点 | `> ⚠️ 风险点：` | 论点可能在评论区或专业读者中引发质疑/攻击 |
| 待增补 | `> ✏️ 待增补：` | 内容单薄，需要创作者补充个人经历或观点 |

**示例**：
```markdown
## 二、百灵 Ring-2.6 在长文本上的表现

展示百灵在 100K+ 上下文场景下的幻觉率与召回数据，对比 Qwen-Max 和 DeepSeek-V3。

> 🔍 待调查：需找到三家最新版本（2026年Q2）的公开测评数据，来源需可溯源。
> ⚠️ 风险点：若测评集非独立第三方，可能被质疑客观度。
```

### 2.5 等待反馈
呈现大纲后必须停止一切动作，等待用户提出修改意见或确认。**严禁**主动触发 Deep Research。
