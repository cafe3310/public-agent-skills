# 开发者参考 (FOR_DEV.md)

本文件供开发和排查技能时使用，不建立任何文档链接。

---

## 1. 开发与设计方法

### 1.1 调性对齐
Agent 的输出文风受读入指令（如 `SKILL.md`、`workflows/`、`rules/`）影响极大。编写这些文件时必须避免「值得一提的是」、「总之」等大模型腔调词汇。保持指令平实直白、步骤具体，防止 Agent 输出被污染。

### 1.2 平台规约定义
在 `rules/platforms.md` 中新增平台规范时，按以下三个维度划分：
- 实施什么：排版格式、Hook 公式及特定切分符。
- 传递什么感觉：读者画像与人设语气。
- 避免什么：各平台避坑指南与坏味道清单。

---

## 2. 问题排查与纠正

通过收集实际运行环境中的生成轨迹日志来做订正。重点排查以下问题：

- 用户纠正：检索日志中用户的否定性回复。若用户需要进行强行矫正，说明前置流程的判定条件或引导话术有漏洞。
- Agent 推脱：留意 Agent 是否找借口不执行 `deep-research` 等子技能。若有此倾向，需在对应步骤中写入强约束指令。
- 路径解析：确认 Agent 没有混淆「技能静态资源目录」与「用户项目输出目录」。
- 工具链容错：追踪失败的工具调用，在 workflow 中补充自动降级逻辑（如 `agent-browser` 降级为 `webfetch` 或 `search_web`），确保流程不卡死。

---

## 3. 语料与素材建设

- 图文切分：对于小红书等包含卡片图文的样例，必须使用专属分割线 `--- 📌 XHS_POST_TEXT_AND_DETAIL_DELIMITER 📌 ---` 将外层正文与图片长图文明确切分，以便后续子技能读取。
- OCR 识别与清洗：批量转写时需用 Shell 循环逐张处理，防止内存溢出。人工校正偏旁误识和乱码，并在头部补充 YAML 元数据，平铺保存至 `samples/` 下。
