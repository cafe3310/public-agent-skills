# Phase 7: 交付包封装 (Handover Packaging)

## 目标
将零散的剪辑素材、定格截图与分镜脚本封装为面向视频剪辑师（Editor）的专业交付包。通过简化的结构和清晰的说明，降低沟通成本，确保叙事逻辑被准确传达。

## 操作步骤

1. **创建包结构 (Package Initialization)**:
   - 在工作区根目录下创建名为 `[交付包名称] version [N]` 的目录。
   - 子目录建议：
     - `clipped_assets/`: 存放加工后的素材。
     - `README_制作说明.md`: 面向剪辑师的导引。
     - `详细分镜执行脚本.md`: 复制一份最新的分镜脚本。

2. **素材简化与迁移 (Asset Simplification)**:
   - **简化命名**: 移除目录名中的日期前缀和冗余后缀。
   - **格式规范**: 目录名统一为 `{model_name} {case_no} {case_name}`（例如 `ring-2.6-1t 07 修复Bug`）。
   - **目录扁平化**: 移除多余的中间层级（如 `collection 2/` 等），确保素材直接位于项目目录下。
   - **同步 Log**: 将对应的 `CLIPPING_LOG.md` 也拷贝入内，方便剪辑师溯源原始录屏。

3. **脚本路径同步 (Storyboard Path Sync)**:
   - 修改交付包内的 `详细分镜执行脚本.md`。
   - **动作**: 将所有素材引用路径（Link）指向包内的 `./clipped_assets/...` 相对路径。
   - **动作**: 标记所有已就绪的素材（使用 🟩）。

4. **编写制作说明 (README for Editor)**:
   - 包含以下核心版块：
     - **叙事逻辑**: 强调本项目的核心卖点（如“自动修复”、“审美进化”）。
     - **创作自由度**: 明确分镜脚本仅供参考，支持剪辑师根据节奏灵活调整。
     - **技术要点**: 提示关键的 Zoom In 细节（如思考链文本）和快进/慢动作的建议。

5. **校验与分发 (Validation)**:
   - 检查包内所有链接是否有效。
   - 确认关键结果图（Screenshot）已包含在内。

6. **版本管理与更新 (Versioning & Updates)**:
   - **包记录**: 在 `notes/` 目录下维护 `yyyy-mm-dd-hh 交付日志 {名字}.md`，记录每次发出的素材包结构快照（可以使用 `tree` 命令获取）。
   - **更新逻辑**: 
     - 允许对同版本包进行覆盖式更新，或创建新的 version 目录。
     - 若发生更新，必须在包内额外生成一份 `UPDATE_NOTES.md` (更新说明)，列出新增、替换或修正的具体素材。
   - **历史追溯**: 确保 `交付日志` 中记录了每个包的交付日期、包含的场景 ID 以及对应的脚本版本。

## 完成标准
- [ ] 交付包目录结构简洁，不含临时文件。
- [ ] 分镜脚本中的所有 🟩 链接均能在包内正确打开。
- [ ] 包含一份针对该版本素材的 `README_制作说明.md`。
- [ ] `notes/` 目录下的 `交付日志` 已同步本次交付的目录树快照。
- [ ] (若为更新包) 包含 `UPDATE_NOTES.md` 说明变更点。
