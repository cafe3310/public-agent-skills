# 模型评价与宣发底稿标准 (Model Brief Standard)

本规范定义了 Phase 5 (Evaluation & Insights) 产出的核心文档结构。该文档不仅是技术评价，更是面向运营、市场及 KOL 的执行底稿。

## 1. 文档元数据 (Metadata)

必须包含日期时间前缀，并遵循以下 Frontmatter 格式：
```markdown
---
title: YYYY-MM-DD-HH 模型评价 - {Model-Name} - {Version}
date created: YYYY-MM-DD Day Time
target: [关联的 Playground 或 演示项目链接]
---
```

## 2. 核心价值与能力表述 (Core Value Proposition)

从宏观角度定义模型的身位（Positioning）。
- **任务规划能力**: 模型作为“主脑”的逻辑表现。
- **工程处理能力**: 在真实代码/项目环境下的生存能力。
- **Agent 协同特征**: 工具调用、多轮对话的可控性。
- **效率表现 (Efficiency)**: 如 Token Efficiency、非思考模型的克制性等。
- **协同价值**: 与其他模型（如 Flash 版）的互补关系。
- **不宜夸大的点 (Boundary)**: 诚实记录当前的短板或“裸奔”风险。

## 3. 运营 Brief (Operational Brief)

将技术语言翻译为市场语言，提供给运营与 Agency。
- **一句话定位**: 极其简练的传播口径。
- **重点强调的能力**: 分点说明，每个点需包含“为什么这在传播中有价值”。
- **目标用户与痛点**: 明确演示要触达的人群。

## 4. KOL / KOC 调优指南 (Usage Tips)

指导内容创作者如何获得最佳效果（Best Practices）。
- **模型特质提醒**: 提醒模型是否为非思考模型、温度建议等。
- **三招制胜**: 给出 3 个通用的、能显著提升产出质量的提示词技巧。
- **进阶策略**: 如“先 Plan 后执行”、“定期刷新提示词”等。

## 5. 陷阱与控制手册 (Pitfall & Control Table)

以表格形式列出常见翻车现场及对应的解法。
| Pitfall | 典型触发场景 | 控制方法 |
| :--- | :--- | :--- |
| 指令模糊导致结果平凡 | 网页生成、文案 | 明确目标、风格；先扩充 Prompt |
| 复杂任务拆不清 | 抽象 Agent 任务 | 配 Plan Tool 或强制列计划 |
| 角色/风格漂移 | 长对话 | 定期重注角色提示词 |
| 结构化闭合错误 | 大型代码生成 | 拆组件；加 Linter 校验 |

## 6. 案例推荐组合 (Demo Portfolio)

按优先级（P0, P1）规划推荐的演示任务。每个案例需包含：
- **定位与选型原因**: 为什么要用这个模型做这个 Demo。
- **执行建议**: 推荐使用的客户端、工具链（如 LangGraph, Claude Code）。
- **核心卖点 (Hook)**: 一句能抓住眼球的话。
- **视觉记录点**: 推荐的截图位置、录屏关键帧。

## 7. 待验证清单 (Verification Checklist) 🟥

列出仍需通过 Phase 3/4 进一步测试的红线区域。
- **网页生成验证**: 审美稳定性、组件完整度。
- **Coding 能力验证**: 工具调用准确率、自修能力。
- **对话稳定性验证**: 指代消解、角色维持。
- **工作流验证**: 不同 Steering / Harness 下的稳定性。

## 8. 示例与提示词库 (Prompt Library)

记录在评估过程中发现的“神级提示词”或 Few-shot 样本。
- 区分不同任务场景（创意写作、代码修改、知识提取）。
- 强调“给样本优于给定义”的原则。
