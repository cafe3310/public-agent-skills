## 核心价值与能力表述

### 1. 复杂任务与规划能力
Releasing-Model-Max 适合定位为复杂任务的主规划模型，能力比较全面。模型更适合分析问题并将混乱输入整理成可推进的结果，而非主打闲聊。尤其适合长材料理解、多材料整合及结构化沉淀。

### 2. 真实工程问题处理能力
模型适合处理真实工程问题，能够读上下文、修改现有代码并持续修复 Bug。适合在真实仓库和明确约束下工作。

### 3. 工具调用与 Agent 工作流能力
已具备较强的工具使用能力，适合接入主流 Agent 框架承担多步任务。

### 4. 非思考模型与 Token Efficiency
Releasing-Model-Max 是一款非思考模型。它默认更克制且省 Token，不会消耗大量推理 Token。在不牺牲任务推进能力的前提下，能将更多 Token 用于理解、规划和输出，因此更具成本可控性。

### 5. 和 Fast 模型的协同价值
Releasing-Model-Max 与 Releasing-Model-Fast 形成分工：Max 负责理解、规划、拆解；Fast 负责快速执行、补全和修补。这种组合更贴近真实生产流程。

### 6. 当前不宜夸大的点
现阶段不应将其包装为“全自动通用 Agent”或“从零写大型项目稳定无误”。应强调在合适的 Harness 和明确约束下的统筹执行能力。

## 运营 Brief —— 全面介绍

### 一句话定位
Releasing-Model-Max 是一款面向复杂任务规划、工程问题处理和 Agent 工作流的万亿级非思考模型，具备极高的 Token Efficiency。

### 重点强调的能力
1. **复杂材料理解与结构化沉淀**: 适合将会议纪要、群聊、零散备注整理成项目 Wiki 或报告。
2. **真实工程问题处理**: 在已有代码基础上进行定位、修改和修复。
3. **Agent 与工具链协同**: 适合接入编程助手环境承担多步任务。
4. **高质量网页与互动展示生成**: 具备较好的审美，适合生成高完成度的页面和互动原型。

## KOL / KOC 第一屏价值提醒

1. **非思考模型特质**: Token 使用克制，不自动展开长思考链。建议提供明确指令以获得丰富结果。
2. **提升结果的三种方法**: 明确工作流、让模型先优化提示词、提供准确描述（目标、风格、边界）。
3. **抽象任务处理**: 采用“先 Plan 后执行”的策略。
4. **长对话建议**: 定期刷新角色提示词，避免角色漂移。

## 陷阱与控制手册 (Pitfall)

| Pitfall | 典型触发场景 | 控制方法 |
| :--- | :--- | :--- |
| 指令模糊导致结果平凡 | 网页生成、文案 | 明确目标与风格；先扩充 Prompt |
| 抽象任务拆不清 | 复杂 Agent 任务 | 配 Plan Tool 或先列计划 |
| 长对话丢角色 | 陪伴型 Agent | 每 10 轮左右重注提示词 |
| 结构闭合错误 | 大型代码生成 | 拆组件；加 Linter 校验 |
