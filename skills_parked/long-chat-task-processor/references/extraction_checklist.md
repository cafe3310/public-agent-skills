# 聊天记录提取检查清单 (Extraction Checklist)

在处理每一个聊天片段 (Section) 时，请对照此清单进行自我检查。

## 1. 任务提取 (Task Extraction)

- [ ] **明确指令**：是否提取了所有明确的 `@某人` 或 `请...` 的指令？
- [ ] **隐含承诺**：是否提取了 `我来看看`、`正在搞`、`晚点给` 这类隐含的接手动作？
- [ ] **状态完整性**：
    - 如果回复了 `OK` / `收到` -> 标记为 `Status: CONFIRMED`
    - 如果回复了 `搞定` / `Done` -> 标记为 `Status: DONE`
    - 如果没有明确回复 -> 标记为 `Status: UNCONFIRMED`
- [ ] **拒绝与转派**：留意 `这个不是我负责` 或 `转给 @某某` 的情况，更新 Assignee。

## 2. 落单任务识别 (Orphaned Task Detection)

- [ ] **无回音的问句**：是否有以 `?` 结尾，且后续 5 条消息内无相关回复的句子？
    - *Action*: 记录为 `落单任务`，Assignee 标记为 `?` 或上下文推测的默认负责人。
- [ ] **被中断的话题**：是否有人发起话题，被插楼打断后，再也没续上？
    - *Action*: 记录为 `潜在遗漏`。
- [ ] **悬空的 @**：是否有 `@某人` 但该人未在后续出现的？

## 3. 时间与上下文 (Time & Context)

- [ ] **绝对时间推导**：
    - 文档中常使用 `-- 02-09 15:00` 形式标记时间。
    - 聊天记录里的 `10:30` 是哪一天？
    - *Action*: 向上回溯查找最近的时间锚点（如 `# 2026-02-09` 或 `-- 02-09`），组合成绝对时间。
- [ ] **代词消解**：
    - `那个文档` 指的是哪个？
    - *Action*: 在同片段上方寻找最近发送的链接或文件名，并在任务描述中备注 `(指：XXX文档)`。

## 4. 关键资产 (Critical Assets)

- [ ] **链接**：提取所有 URL（文档、PR、工单、设计稿）。
- [ ] **图片**：聊天记录中如果有 `[图片]` 占位符，且上下文在讨论该图，请记录“此处有图片，关于XXX”。

## 5. 决策 (Decisions)

- [ ] **结论性词汇**：搜索 `结论是`、`那就这么定`、`先这样`。
- [ ] **变更**：搜索 `不要用`、`改用`、`废弃`。
