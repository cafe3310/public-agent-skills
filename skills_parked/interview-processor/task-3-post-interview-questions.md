# 子任务 3：整理真实提问 (Post-Interview Questions Extraction)

本指南用于在面试结束后，从录音转写文本中完整提取、纠错并规范化面试官所提出的所有真实问题与追问，并可选地沉淀到知识图谱中。

---

## 1. 输入数据 (Inputs)
- **录音转写文本** (语音转文字的原始文本，通常包含大量的口语化词汇、同音错别字和语气词)
- **候选人简历/基本信息** (用于确认候选人姓名和招聘类型)

---

## 2. 执行步骤 (Workflow Steps)

### Step 1: 真实提问过滤与纠错
Agent 读取语音转写文本，剔除寒暄、候选人长篇回答和无实质提问的废话。识别转写中的同音字错别字（如：将“协程”识别为“行程”、“协防”；将“Flutter”识别为“福莱特”等）。

### Step 2: 口语化改写
将面试官现场口语化的发问（例如：“额...那个...你对那个...动态化，比如 Flutter 这种，是怎么看的啊？就是你实际用过吗？”）改写为书面通顺的技术提问（例如：“请谈谈你对动态化技术（如 Flutter）的理解，以及你在实际项目中的应用经验。”）。

### Step 3: 问题结构化归类
按技术/业务方向（如：计算机基础、前端工程化、架构设计、项目实战、职业素养等）进行大类划分。每个问题要保留其配套的**深入追问**链路。

---

## 3. 问题整理 Prompt 模板 (System Prompt)

请使用以下 Prompt 指引 LLM 进行问题提炼：

```markdown
你是一名专业的招聘助理。请从以下面试录音转写文本中，提炼出面试官所问过的所有真实问题。

### 限制与要求
1. **真实提问还原**：只提炼面试官真实发问的问题，不要添加面试官没有问过的问题。
2. **追问链路完整**：保留面试官针对某一个主题的连续追问，使用子列表展示。
3. **语音纠错**：根据上下文专业术语，纠正语音转写造成的同音词或语病。
4. **口语改书面**：将口语化的问法提炼为书面化、条理清晰的技术或业务问题。
5. **识别招聘类型**：从输入中识别候选人的姓名，并判断属于“校招”、“社招”还是“数字马力招聘”（数字马力为生态外包用工类型）。

### 输入数据
- 候选人信息: [此处插入基本信息]
- 语音转写文本: 
  [此处插入转写文本]

### 输出格式规范 (Markdown)

### 基本信息

候选人姓名： [姓名]
招聘类型： [校招/社招/数字马力招聘]

### 面试官提问汇总

#### [方向一：例如 计算机基础与语言认知]

1. [书面化后的主问题]
    a. [书面化后的追问 1]
    b. [书面化后的追问 2]
2. [主问题 2]

#### [方向二：例如 项目实战与无障碍设计]

1. [主问题]
```

---

## 4. 知识图谱沉淀指引 (KG Storage)

整理出提问汇总后，Agent 可以将其沉淀进知识图谱中。

1. **命名规范**：`[领域/岗位]面试问题集-YYYYMMDD` (例如：`大模型产品面试问题集-20260527`)
2. **实体类型 (type)**：`面试问题集`
3. **写入操作**：
   - 运行以下命令，将问题集存入知识库：
     ```bash
     echo "# [领域/岗位]面试问题集-YYYYMMDD
     
     ## [方向一]
     - [问题 1]
     - [问题 2]
     
     ## [方向二]
     - [问题 3]" | memocli create-entity -p <path> -e "[领域/岗位]面试问题集-YYYYMMDD" -t "面试问题集" --content-stdin --add-rel-out "target_methodology:[领域/岗位]专家面试风格-YYYYMMDD" --reason "沉淀面试真实提问集"
     ```
   - *注：请根据岗位实际情况，将出站关系指向对应的面试风格实体。*
