说个唱反调的事情，在我看来 OpenClaw 在国内的火爆程度，整个风气已经跑偏了。

而且，我的观点一贯是鲜明的、明确的，那就是：就目前的 OpenClaw 能力和成熟度来讲，对于一般的普通用户屁用都没有。

最近 OpenClaw 频繁登上国内各个内容平台的热搜榜，让很多人都变得焦虑异常，感觉不给自己的电脑或者在云端部署一个 OpenClaw ，自己就要被淘汰了一样。

看看腾讯免费推出的部署龙虾服务的场景，那场面简直人山人海，真的是一代人有一代人的鸡蛋要领。

老年人参加一个活动或者起个大早去超市领免费的鸡蛋，最起码鸡蛋吃到嘴里能够营养身体，但是，龙虾可不是啊，龙虾是个吞金兽啊。

前一段时间我部署了一个，特么跑了也就 3 个任务，200 块钱没了，连半天都不到的时间，token 简直是在燃烧，看着都心疼。

普通打工人一天的工资恐怕都养不起龙虾一天的饭钱。

何况大多数用户都是价格敏感群体呢，一般都喜欢使用免费软件，那么排队让别人免费安装部署 OpenClaw 的用户大概率可能还不知道养龙虾是花钱的，光看到免费部署的服务字样了。

其实，是帮你免费部署到了云端了，服务器资源不花钱吗？在云端服务器跑大模型消耗 token 更费钱。

多少人 AI 会员都没有充过，API 更不会用，装上能干什么？

让龙虾帮你干活，你得对接 MCP 服务，你得下载和配置 Skills ，其中就涉及到了各种 API 的对接和 API key 的配置。

大多数普通人都不懂，如果你不会安装 MCP 和配置 Skills ，你用龙虾顶多就是帮你写个文案。

不信，你让龙虾帮你爬个虫，它都得告诉你：这些文章都有反爬虫机制或者验证机制，需要你的浏览器 cookie 等信息或者，需要你对接官方网站 of 它的 API 才行，一句话把你顶回来了。

普通用户哪懂这些啊？

如果是云端部署的龙虾更让你抓瞎，都是 Linux/Unix 系统，龙虾说我要模拟登录，在浏览器中帮你爬虫吧，但是，需要你安装浏览器才能爬虫。

可是，云端服务器 Linux/Unix 系统，浏览器怎么安装啊？抓瞎了吧？安装到本地龙虾还行，但是，本地龙虾服务又不安全啊，毕竟 OpenClaw 是一个奥地利个人开发者做的，安全机制不健全啊，有时候，龙虾还动不动删你文件，咋办？

云端服务器部署的，还有一个问题，那就是：远程登录服务器可能你都不会，龙虾帮你干完活，文件你都不知道怎么拿出来，更别提在这样的系统里配置各种服务了。

一句话：如果你自己连安装都不会，安装部署龙虾已经很简单了，即使别人帮你装上了，你都不知道用它干啥。

说实话，OpenClaw 这个产品有它自己的优势，它的产品思路很不错，但是，不成熟，而且，我个人感觉全自动化的东西本身就不安全，我上个月的时候，就差点翻车，龙虾帮我写了一篇文章，但是，我全自动化的流程是发布到草稿箱，发布之前，我需要确认，幸亏我看了文章，那篇文章写的很敏感，一旦发出去，我感觉有被封号的风险。

另外，现在 OpenClaw 真的能给大家带来什么实际产出吗？吹爆 OpenClaw 的那些 AI 博主或者自媒体账号，所有的宣传口吻就是自动化发布，帮我写文章，自动发布到各平台，但是，这恰恰就是最不实用的。

程序员用 OpenClaw 写代码还算比较实用的产出。

普通人不就是用它帮你写写文案，制作个报告的？OpenClaw 这么费 token，用 OpenClaw 还不如用现成的 ChatGPT、Claude、豆包、千问这些 AI Chat 软件更实用呢。

真的，冷静一下吧，真的没必要追风安装这个龙虾。

很多朋友问我你为什么不太喜欢使用 OpenClaw 呢？其实，我真的没啥感觉，我从本质上其实不是特别喜欢这种全自动的东西。

真到了要干活的时候，我还是会打开 Claude Code，迭代 Skill，跑任务，效率就是摆在那的。

OpenClaw 龙虾虽火，但说实话，操作演示没问题，可要论实用性，跟 Claude Code 加 Skills 比起来，差距还是挺明显的。不知道为什么我总感觉龙虾像一个大型的玩具。

小龙虾的框架设计我是认可的，IM 接入、记忆系统、心跳机制、Skill 整合，该有的都有，上手简单，还能不断进化，对普通用户来说确实也友好。

可稳定性是个绕不开的坎。每天刷社群，全是大家在救龙虾的，今天挂了明天又崩了，这就很影响日常使用了。

工具好不好，最终看你能不能靠它把事情做完。架构好看是加分项，稳定跑起来才是基本盘。

So，我认为 OpenClaw 虽然易用，但是不实用。OpenClaw 能干的事情，其实用 Claude Code 也都能干。

有那部署安装 OpenClaw 的心思，不如好好研究一下 Claude Code 。
