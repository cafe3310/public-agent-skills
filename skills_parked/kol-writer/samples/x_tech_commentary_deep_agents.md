Agents 1.0 -> Agents 2.0：浅层循环 -> 深层智能体 —— 来自 @_philschmid 的博客

### 浅层智能体 (Shallow Loops) 的局限：简单却脆弱

浅层智能体的工作原理：它本质上是一个简单的“while 循环”，通过用户提示、LLM 推理、工具调用（如搜索）和观察输出反复迭代。

这种设计依赖 LLM 的上下文窗口作为唯一状态，适合短期、事务性任务，例如“东京天气如何？我该穿什么衣服？”只需几步即可完成。 

然而，当任务扩展到多步复杂场景——如“研究10家竞争对手、分析定价模型、构建比较表格并撰写战略摘要”——浅层智能体就会暴露问题：上下文溢出（噪声数据如 HTML 碎片挤占核心指令）、目标丢失（中间步骤模糊初始意图）以及缺乏恢复机制（无法从错误中回溯）。结果往往是无限循环、幻觉或彻底失败。作者直言：“浅层智能体擅长5-15步的任务，却对500步的任务一筹莫展。”

### 深层智能体 (Deep Agent)：四个支柱的架构革命

深层智能体的架构设计，它将规划与执行解耦，并将状态外部化，避免 LLM 上下文的瓶颈。这种“深层”并非指模型深度，而是指系统在处理长时序、多层次任务时的鲁棒性（如跨越数天的50步流程）。作者提炼出四个关键支柱，形成一个模块化框架：

1. **显式规划**：智能体使用工具生成动态计划（如 Markdown 待办列表），实时更新状态（待办中、进行中、已完成），并添加备注。这不同于浅层智能体的隐式链式思考，而是可修订的外部结构，帮助智能体在失败时适应，而非盲目重试。

2. **分层委托（子智能体）**：引入“协调器”（Orchestrator）角色，将任务拆解为子任务，委托给专职子智能体（如研究者、编码器、撰写者）。每个子智能体在独立干净的上下文中运行工具循环，仅返回合成结果给协调器。这种分工避免单一智能体“样样通却样样松”，提升效率 and 专注度。

3. **持久记忆**：状态不再局限于 LLM 窗口，而是存储在外部介质（如文件系统或向量数据库）。智能体可读写中间结果（如代码草稿或原始数据），通过路径或查询检索相关片段。Claude Code 和 Manus 等框架作为实现工具，确保可扩展性。

4. **极端上下文工程**：通过数千 token 的详细提示定义协议，包括规划规范、子智能体生成规则、工具使用和文件结构，甚至融入人类协作环节。这要求开发者优化提示，而非简化，以匹配更智能模型的潜力。

这些支柱共同实现“控制上下文即控制复杂性”，让深层智能体从反应式转向主动式，适用于小时或数天级的任务。

### 实际示例与可视化

为解释深层智能体，博客提供了一个序列图示例：任务“研究量子计算并将摘要写入文件”。流程从用户请求到协调器规划，再到委托子智能体（如研究者使用持久记忆收集数据），最终合成输出。图中清晰展示组件间交互，突出子任务的隔离与记忆的读写。 这与浅层智能体的单循环形成鲜明对比，后者在此类任务中易迷失方向。

---

### 创新与影响：从工程到未来的范式

相较浅层循环，深层智能体的创新在于模块化和可扩展性：它整合智能体模式（agentic patterns）、持久状态和子智能体，实现从“记住一切”到“知道何处查找”的转变。文章客观指出，这种设计并非万能解，而是针对复杂问题的工程优化，强调开发者需围绕 LLM 构建系统，而非仅添加工具。
