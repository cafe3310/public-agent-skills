# 子流程 05: 大纲微调 (Iteration & Optimization)

## 1. 目标
由创作者主导大纲修改，将个人洞察、文风偏好与独特观点融入大纲，直至确认满意。

---

## 2. 执行规程

### 2.1 触发提示
检索报告输出后，向用户提示：
```markdown
检索已完成。大纲已更新，请审阅并提出修改意见或补充想法。
```

### 2.2 迭代修改规则
- **创作者主导**：用户可随时提出修改要求（如调整观点方向、加入特定案例/金句、调整段落顺序或删除部分内容）。
- **Agent 执行**：根据用户反馈对 `03-大纲草稿.md` 进行精准的局部修改，严禁改动未提及的上下文。修改后简要告知改动点。
- **标注更新**：若用户针对大纲中 `> ⚠️ 风险点` 或 `> ✏️ 待增补` 标记给出了补充内容或决策，移除对应的 Blockquote；未处理的标记予以保留。

### 2.3 参考文风样本与规范
修改大纲或文章草稿的语气与排版时，Agent 需读取并遵循以下规范：
1. **加载文风参考**：
   - **自定义参考**：检查并读取 `01-用户原始输入.md` 中的「文风参考样本」（若为本地路径，直接读取文件）。
   - **内置样例**：读取 `samples/` 目录下的博主样本（如 `samples/xhs_tech_expert.md`）。
   - **平台与字词规约**：调用 `rules/platforms.md`（确保排版与 Hook 契合平台）和 `rules/ai_artifacts_blacklist.md`（剔除大模型腔调词汇）。
2. **文风应用**：
   - 提取样例在句式长短、口语语气词频率、指代词使用上的偏好。
   - 扩写草稿或去 AI 腔调重构时，向用户简要说明文风调整策略（如：段落合并、因果表述替换等）。
   - 坚持局部精准修改原则，修改后的内容输出至独立的新文件中，不要直接覆盖原始草稿。

### 2.4 结束判定
当用户明确确认满意（如「可以了」、「终稿吧」），Agent 结束迭代，输出简短总结：
```markdown
大纲微调完成。本轮共迭代 [N] 次，主要修改点：
- [修改点 1]
- [修改点 2]

仍保留 [M] 处待后续处理的标注。我将开始生成终稿文件。
```
随后进入「终稿归档」阶段。
